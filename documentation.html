Lightweight Time-in-Status — Documentation

A Jira Cloud app that shows how long issues spend in each workflow status, so you can see where work actually gets stuck — without leaving Jira.

Getting started

After installing the app on your Jira Cloud site, no setup is required to start seeing data — every surface works immediately with sensible defaults. Project admins can optionally fine-tune thresholds and duration behavior in Project Settings.

Issue Panel

Open any issue and look for the Time in Status panel. It shows a badge for each status the issue has passed through, with how long it spent there. The status the issue is currently in is shown as active; any status that has exceeded its configured threshold (48 hours by default) is visually flagged as stale.

Opening an Epic shows this same per-status breakdown for the Epic issue itself, plus a rolled-up summary of its child issues (see Epic Rollup) in the same panel.

Project Dashboard

Accessible from the project sidebar, the dashboard aggregates time-in-status across the whole project:

  • Per-status issue counts, total time, average time, and median time
  • Bottleneck statuses highlighted based on your configured thresholds
  • Average and median cycle time (work started → done) and lead time (created → done), derived from Jira's own status categories, so it works with custom workflows
  • Filters by issue type and by Epic

The dashboard is computed live from Jira each time you open it or change a filter, considering up to the 500 most recently updated issues in the project. If a project has more than that, the dashboard states that the data is based on the 500 most recent rather than silently showing partial numbers.

Epic Rollup

Open any Epic issue to see time-in-status aggregated across its child issues directly in the issue panel — no need to filter the project dashboard by hand. Epic Rollup considers up to 200 child issues; if an epic has more, the panel states that the results are capped rather than silently truncating.

Project Settings

Project admins (not visible to non-admins) can configure, per project:

  • Stale/SLA thresholds — set a default threshold and override it per status, instead of relying on a single fixed number across every status.
  • Business-day mode — an opt-in toggle that excludes weekends (Saturday/Sunday) from every duration calculation across the issue panel, dashboard, epic rollup, and CSV export. Off by default, so nothing changes unless you turn it on.

Statuses in the Done category are excluded from bottleneck flags and aggregates everywhere in the app, since a finished status isn't a bottleneck.

CSV Export

Both the Project Dashboard and Epic Rollup have a CSV export button that downloads the currently displayed data (respecting active filters on the dashboard) directly to your browser. Nothing is sent to a server other than Jira/Forge to generate it — see the Privacy Policy for details.

Licensing

Without an active license, the issue panel, dashboard, and settings pages show a clear "license required" message rather than partial or broken data.

FAQ

Does this work with custom workflows?

Yes. Status names and status categories are read directly from your project's own workflow configuration — nothing is hardcoded to a specific set of status names.

Does the app store my issue data?

No. Durations are calculated live from Jira on each page view and are not persisted. The only thing the app stores is the threshold/business-day configuration a project admin sets. See the Privacy Policy for full details.

Why is my dashboard only showing some of my issues?

The dashboard and epic rollup cap how many issues they process per load (500 for the project dashboard, 200 for an epic's children) to stay within Jira's API limits. If you're above the cap, the app tells you so directly in the UI rather than showing incomplete numbers unlabeled.
